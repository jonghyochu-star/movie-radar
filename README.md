# Movie Radar · 1.5

해외 영화·드라마의 짧은 영상 후보를 찾고, 좋아요 보관함과 제작 후보로 선별하는 개인용 GitHub Pages 앱입니다.

## 1.5 핵심 변경

- **후보 풀 확장**: 한 번의 live 실행에서 검색 주제를 4개 → 6개로 늘렸습니다. 각 주제는 최근/전체 기간을 나눠 검색하므로 정상 실행 기준 `search.list`는 최대 12회입니다.
- **좋아요 씨앗**: 브라우저에서 좋아요한 YouTube 영상 ID를 최대 8개 복사해 Actions의 `seed_video_ids`에 붙여넣을 수 있습니다. 수집기는 좋아요 영상 자체를 재추천하지 않고, 해당 채널의 다른 업로드를 추가 출처로 확인합니다.
- **중복 이력 캐시**: GitHub Actions cache에 최근 수집 ID와 보수적인 제목 지문을 저장해 1→2→3차 재탐색에서 반복을 줄입니다.
- **할당량 표시**: 앱의 `이번 수집 경로 보기`에서 이번 실행의 `search.list` 호출 수와 기타 API 호출 수를 보여줍니다. 프로젝트 전체의 남은 일일 할당량은 Google Cloud에서 확인해야 합니다.
- **기존 하드 조건 유지**: 화면의 구독자·조회수·길이·언어·원작 확인·쇼츠 확인 기준을 자동 완화하지 않습니다.

## 다음 수집 방법

GitHub `Actions → Movie Radar → Run workflow`에서:

- `mode`: `live`
- `collect_preset`: 보통 `english_focus`
- `custom_weights`: custom 모드가 아니면 비움
- `retry_round`: 1 / 2 / 3
- `seed_video_ids`: 앱의 **좋아요 씨앗 ID 복사** 버튼으로 복사한 값. 좋아요가 없으면 비워도 됩니다.

`english_focus`의 검색 주제 6개는 기본적으로 영어 4개와 순환하는 다른 언어 2개로 구성됩니다. 언어 설정은 원작 제작국 판정이 아닙니다.

## 좋아요 씨앗의 의미

좋아요는 브라우저 `localStorage`에만 저장되므로 공개 Pages가 GitHub Actions에 자동 전송하지 않습니다. 보안상 토큰을 웹앱에 넣지 않고, 사용자가 공개 YouTube 영상 ID만 명시적으로 붙여넣는 방식입니다.

씨앗 영상은 최대 8개, 씨앗 채널은 최대 4개를 사용합니다. 씨앗 채널은 채널당 최대 2페이지(최대 100개 최근 업로드)를 확인합니다. 같은 채널이라고 감동결이 같다고 판단하지 않으며, 이후 기존 메타데이터/언어/화면 필터를 그대로 적용합니다.

## 할당량

Movie Radar는 이번 실행이 실제로 사용한 호출 수만 표시합니다. 프로젝트 전체의 오늘 잔여량은 API 키만으로 알 수 없으므로 Google Cloud Console에서 확인해야 합니다. 1.5 기본 설정은 한 live 실행에 검색 주제 6개 × 최근/전체 = 최대 12회의 `search.list` 호출을 계획합니다(네트워크 재시도는 별도).

## 저장과 개인정보

좋아요·별로·제작 단계·메모는 사용자의 브라우저에 저장됩니다. API 키는 GitHub Repository Secret `YOUTUBE_API_KEY`에서만 사용하고 공개 출력에 쓰지 않습니다. 사용자 기록 백업 파일에는 API 키를 넣지 않습니다.
