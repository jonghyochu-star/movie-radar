# Movie Radar · 1.7

Movie Radar 1.7은 지금까지의 테스트 결과를 바탕으로 **수집 순서를 다시 설계한 버전**입니다.

## 1.7의 핵심 변화

기존 흐름은 `감동 검색어로 넓게 수집 → 나중에 영화/드라마 여부 확인`에 가까웠습니다. 이 방식은 인터뷰·제품·일반인 영상까지 많이 섞였습니다.

1.7은 다음 순서로 바뀝니다.

1. **YouTube Movies / TV shows 주제 안에서 먼저 검색**
2. 그 안에서 가족·관계 회복·친절·존엄·유머·노력·새로운 감동결 등의 검색 경로 사용
3. 최근/전체 기간을 각각 조회하되 조회수 우선 순서를 사용
4. 좋아요 씨앗/참고 채널은 보조 출처로만 사용
5. 씨앗/참고 채널에서만 발견된 후보는 영화·드라마 메타데이터 근거가 있어야 통과
6. 한 채널 쏠림을 제한한 최대 40개 검토 풀 생성
7. 브라우저의 좋아요 기록은 같은 근거 수준 안에서 표시 순서에만 반영

## 공식 API 근거와 한계

- Movies topic: `/m/02vxn`
- TV shows topic: `/m/0f2f9`
- YouTube `search.list`의 `topicId`는 해당 주제와 연관된 결과를 제한하는 검색 게이트입니다.
- `videoDuration=short`는 YouTube Shorts 자체가 아니라 **4분 미만 영상**을 뜻합니다. Movie Radar는 이후 `videos.list`의 실제 duration을 다시 읽어 0~180초 범위를 적용합니다.
- topicId, 제목, 설명, 태그, 카테고리는 **영화·드라마 장면임을 완전히 증명하지 않습니다.** 실제 장면·원작 제작국·감동결·Shorts 여부는 별도 확인이 필요합니다.

공식 문서:
- https://developers.google.com/youtube/v3/docs/search/list
- https://developers.google.com/youtube/v3/docs/videos

## 구독자 수 정책 변경

1.7에서는 **작은 채널을 우선하는 로직을 수집 우선순위에서 제거**했습니다.

기본 화면:
- 최대 구독자: 제한 없음
- 최소 조회수: 10만 이상
- 영상 길이: 0~180초
- 영상 종류: 영화·드라마 수집 게이트 통과

구독자 수와 조회÷구독 비율은 카드에서 참고할 수 있지만, 큰 채널이라는 이유로 후보를 뒤로 보내지 않습니다.

## 검토 풀 정책

`discovery.json` 기본값:
- review_pool_limit: 40
- per_channel_limit: 3
- seed_pool_percent: 25
- reference_pool_percent: 10
- seed_pages_per_channel: 1
- screen_topics: movie + tv
- source_requires_screen_evidence: true

## 좋아요 취향 반영

좋아요는 두 방식으로 사용됩니다.

1. **로컬 정렬:** 현재 브라우저에서 좋아요한 영상과 같은 채널/탐색 경로 후보를 같은 근거 수준 안에서 위쪽에 표시
2. **씨앗 ID:** 사용자가 `seed_video_ids`에 직접 붙여넣은 영상의 채널을 보조 출처로 탐색

좋아요가 후보를 삭제하거나 자동으로 정답을 만드는 것은 아닙니다. 한국 영화 제외·일반 영상 제외·영화/드라마 아님은 취향 신호와 별도로 저장됩니다.

## 이번 버전의 현실적인 목표

1.7의 목표는 “AI가 모든 장면을 보고 완벽하게 취향을 판정”하는 것이 아닙니다.

목표는:

> 수백 개의 무관한 영상에서 사람이 찾는 대신, 영화·드라마 관련성이 높은 20~40개 후보로 줄이고, 조회수와 좋아요 기록을 이용해 볼 순서를 점점 개선하는 것.

이 목표가 실제 테스트에서 어느 정도 달성되는지 확인한 뒤 다음 단계의 자동화 수준을 결정합니다.
